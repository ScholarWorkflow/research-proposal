# 改稿、交付格式与恢复

## 采用用户修改稿

用户指定本轮采用的 Markdown 或 Word 后，先读当前正式状态，建立新工作版本，用 `import_revision` 保留交回原件并与其 `baseline_body` 比较。返回 AST 是待处理稿，不能直接写成已确认正文。

检查 `changes`、`comments`、`unsupported`：

- 插入、删除和其他未决修订先按用户已说明的接受、拒绝或指定修改处理；尚无决定时展示相关选择。不能默认全部接受或丢弃。
- 批注是反馈，结合上下文处理，不自动成为正文。
- 不能可靠读取的文本框、嵌入对象等，说明实际位置并保留原件；重要内容未处理前不发布省略后的成品。
- Markdown 普通内容差异同样需要判断影响。引用与新事实仍须核对材料。

比较的是用户意图及方案内容。纯措辞、排版或不改变结论的引用修正保留原确认；研究问题变化处理问题确认及受影响方案，核心方法或关键数据条件变化处理方案确认。用户已明确要求的实质修改直接执行并记录原意与来源；文件内意图不明的实质变化先展示改变及影响，只询问受影响部分。

两个相互冲突的版本且没有采用指示时，保留两份原件，展示差别后由用户选择，不按修改时间或文件名决定。导入时不覆盖旧版本；正式保存和导出都在新工作目录。

## 交付格式

当前只交付 Markdown。导出使用 `formats:["md"]`；省略 `formats` 时同样只导出 Markdown。组件从已保存的正式正文生成 Markdown，不读取或复制 Word 模板，不生成 Word、预览 PDF 或页图。

学校提供表格时，仍先读表格本身及说明，不能因招生分析跳过空白表而忽略栏目、语言和篇幅要求；把这些要求组织为 Markdown 的标题和正文，不声称已经填写学校原表。

导出后重新读回 Markdown，检查标题、段落、列表、表格、引用和链接的内容与顺序。`review_revision` 会实际读回 Markdown 与正式正文比较，返回 `checks.content_consistent` 和 `checks.checked_formats:["md"]`；不接受调用者传入的成功标记。正文、引用或 Markdown 文件改变后旧核对失效，必须重新导出并核对，核对成立后才能提交。

Word 模板填入、双格式交付和页面排版调试延期，不是当前交付义务。旧 Word 分支及其 `template_path`、`mapping` 参数作为延期实现保留，当前调用不使用；旧 Word 结果只留在原记录中，不混入新稿交付，也不改写为成功。

## 版本与中断

本稿的 `研究计划状态.json` 是唯一入口，`current` 指向已提交稿，`works` 保存进行中的修订。每次操作消费返回的新 `state_version`；恢复前重新读磁盘，不用旧会话计数。

| 当前情况 | 继续方式 |
|---|---|
| 材料、候选、问题或中文方案保存后中断 | `resume_revision` 后采用仍有效数据，未保存的一步重新做；确认沿用真实记录。 |
| Markdown 导出失败 | 旧提交仍有效；正文未变时只补失败的 Markdown，再重新核对并提交。 |
| 输出内容不一致或核对失败 | 修复本轮问题，再导出和核对受影响结果，不切换当前稿。 |
| 完整目录改名，但状态尚未切换 | 只依 `pending_commit` 指定的修订恢复，重新核对成立才切换；不能扫描目录猜最新版。 |
| 已切换当前状态后中断 | 重报该提交版 Markdown，不重复生成，也不退回旧版。 |
| 输入、正文或用户选择变化 | 按 `next_steps` 重做依赖该变化的部分；无关材料与决定继续使用，实质变化按上面的确认规则处理。 |
| 别的一轮先保存或提交 | 保留本轮工作和新返回内容，报告冲突；重新读当前状态并确定采用版本，不用递增猜测覆盖后来决定。 |

正文变了就不能保留旧的 Markdown 交付。已提交文件被用户修改时，先保留并导入修改原件，再开始新工作版本，不能通过恢复把修改擦掉。旧未提交工作版没有 `delivery_formats` 时，公开 `resume_revision` 会在文件锁内补入 `["md"]`、递增状态版本并只要求重做交付核对；材料、问题、方案、正文及仍有效的用户决定保留。

## 同题申请另一学校

建立独立 `proposal_dir`、申请编号与用途；不要更改旧稿的绑定。读取新学校的实际表格、语言和篇幅，记录用户明确授权复用的文献和通用方案。复用决定指向来源稿与具体范围，不能把旧学校确认无条件复制为新学校全部确认。

在新稿保存复用材料及仍适用的研究问题/方案。已授权且没有改变的部分直接沿用；新要求引发的实质变化只确认受影响部分。新稿的正文、进度、版本和 Markdown 交付各自保存，第一稿和其他教授状态保持原样。
