# 论文前置与交接

本文件只安排缺少的阶段；各阶段的事实生成、参数校验、缓存和收尾继续由原仓库负责。使用当前环境已安装的 `professor-contact`、`professor-collector`、`professor-topic-clustering`，不引用开发目录或从上游 Markdown 拼造正式 JSON。

执行任一 contact 阶段前，读取已安装 `professor-contact/SKILL.md` 的运行入口、原生委派、收尾要求，以及该阶段**完整章节**。调用时只给本阶段业务输入，不把 caller 路由说明复制进子任务。原命名代理必须委派、等待、消费；主线程不得因自己能读论文而代替它。

## 按发现结果继续

| `next_step` | 必要业务与已安装代理 |
|---|---|
| `collect` | `professor-collector`：`folder_path` 为申请资料根，传用户已有教授范围，`skip_pdf:true`。只做初始采集，定向补全文留给第一阶段。 |
| `preview` | `professor-topic-clustering`：同一 `folder_path`、已有教授范围、`preview:true`。摘要分类用于选择范围，不证明全文结论。 |
| `stage0` | `professor-contact`：同一 `folder_path`；用户已有明确教授/方向决定才传其正式选择输入。没有决定也要先委派，让 owner 返回当前真实选项；向用户展示后再把决定交回。 |
| `stage1` | `professor-contact-downloader`：同一 `folder_path`；将阶段 0 成功事务返回的教授本地 `target_state` 原路径按其 `target_files` 格式传入。原 owner 建立/核对候选快照，只补缺少全文。 |
| `stage2` | `professor-contact-analyzer`：同一根与同一目标文件，按已安装完整参数合同传入。原 owner 先核对阶段 1，再预检现有分析、论文身份、来源和缓存；不能按题名或文件名自行挂接分析。 |
| `stage3` | `professor-contact-idea-generator`：只用原检查认可的输入包，指定方向时传精确 `direction_id`。完成下面的 Codex caller 收尾后再重新发现。 |
| `proposal` | 读取已认可输入与候选，进入研究计划自己的问题选择与设计，不运行邮件阶段。 |

每个阶段结束后消费它返回的真实状态和缺项，再运行发现检查以判断下一项。不要为了“从第一步开始”重跑有效输入；也不要把已有分析、某个 Markdown 或候选文件存在当成阶段完成。

零散分析缺 `套磁候选输入.json` 时，先落实该教授的有效 `套磁目标.json` 和 `套磁阶段1候选.json`。目标缺失/失效就补预筛和阶段 0；快照缺失/失效就交阶段 1。两者成立后才能交阶段 2 复用分析，随后阶段 3。有效输入包可直接交阶段 3，不必重跑阶段 2。

同一个教授内可能有多个方向。候选范围由实际 `direction_id` 绑定，不用展示名猜身份。已有上游目标决定可沿用，研究计划的核心问题仍独立保存。`refresh_scope=selected` 读取套磁自己的选择文件，不能用研究计划选择驱动它，也不为此运行套磁第四阶段。需要单方向时用原 `direction_id` 参数。

## 原流程中的用户决定

原流程需要的教授与方向选择、全文访问方式、执行通道、处理范围、全文后方向调整，以及追加校验轮次都必须保留。没有答案时保存可继续的数据和实际问题，不发明默认授权。Codex 子线程返回 `needs_input` 后，主线程向用户展示该次实际选项，后续以原磁盘状态和明确输入继续；不依赖恢复旧子线程。

阶段 0 的选择按 `professor_dir` 与 `preview_path` 标识单教授事务，方向使用 owner 提供的机器编号；显示标签只供用户阅读。已有明确决定可直接传给原 owner 校验保存，主线程不手写目标。

阶段 1 只有需要补全文时才消费 `access_mode`。用户已明确的 `oa_only` 或 `allow_non_oa` 原样传递，未给定时保持缺省并消费 owner 的实际结果；不能把自然语言擅自翻成扩大访问范围的决定。

阶段 2 由 analyzer 决定缓存复用和每篇分析范围；它按原约定调用 `paper-analysis` 及原有校验器。主线程不直接替 analyzer 调论文分析叶子，也不拿摘要级材料充当全文。原方向调整提案未经真实决定时保持未接受。

## Codex 第三阶段必须完成的收尾

第三阶段生成代理在 Codex 下不启动校验子代理；**调用它的本线程**负责以下过程。原样采用已安装 contact 技能中的完整字段及失败处理，不另定义结果格式。

1. 通过本会话 `spawn_agent` 委派准确名称 `professor-contact-idea-generator`，等待结束并消费结果，包括本次 `invocation_file`、`invocation_sha256`。缺少必要结果就保留失败，不补造凭据。
2. 用已安装 `contact_state stage3-prepare-validation` 及返回凭据准备本轮交接，把候选稿路径、`artifact: candidates` 和准备入口给出的 `output_file` 交给准确名称 `professor-contact-style-validator`。真实委派、等待；不要给校验器上游状态、凭据或未要求的文件。
3. 按原合同检查校验器完成报告及指定输出路径；成功后调用 `stage3-save-validation`，紧接 `stage3-record-validation`，均消费准备/保存入口返回的字段。校验正文由固定入口写入和保存，主线程不得摘抄、改写或重建 JSON。
4. 只有记录入口返回 `needs_correction=true` 才把同一凭据与已记录校验文件交回生成代理修正；随后准备下一轮并再真实委派校验器。默认最多两轮，不能失败后自行加轮；需要追加时先展示问题，由真实用户授权并经原入口保存。
5. 终态记录后，用原 `stage3-rebuild-overview --program-root` 尝试重建一次派生总览。总览失败保留原报告，不推翻已成立的教授本地终态，也不为此重跑生成。校验失败终态的风险仍需向用户说明，不能自称校验通过。

完成候选文件只到第一步；`validator` 未记录不算阶段 3 完成。返回前检查：需要委派的阶段是否真实尝试、是否等到结束并消费，第三阶段是否完成原收尾。外部或运行时失败保持原错误与已有材料，不降级为主线程模拟完成。

## 转入研究计划

将认可的 `套磁候选输入.json`、`套磁候选状态.json` 和必要原材料作为本稿输入，保留证据范围与不确定性。作者后续工作在已检查材料内尚未完成，不等于整个领域无人研究。相关研究仍要补查教授之外的来源。

把上游候选解释为少量可选择的问题；说明每个问题的材料依据、方法和风险。用户选择后保存为研究计划自己的问题及确认，不写套磁选择，不编译邮件、不生成邮件。
